Moelven Industrier · AI-dag — Sub-agents
Sub-agents

Sub-agents — egen sesjon, eget kontekstvindu.

Isolert kontekst, egne verktøy. Agenten gjør sitt arbeid og returnerer kun resultatet til hovedsesjonen — uten å fylle den med tool-kall.

Innebygde: Explore (read-only søk), Plan (arkitektur), general-purpose. Egne i ~/.claude/agents/.

Når dra inn en agent
  • Søk som vil sprenge konteksten
  • Uavhengig deloppgave
  • Skal kjøres samtidig som du jobber
  • Trenger isolert kontekst eller egen branch

Liten oppgave som hører her? Gjør det selv — agent er overkill.

Skills · anatomi

Anatomien til en skill.

En mappe i ~/.claude/skills/<navn>/ med en SKILL.md-fil. Frontmatter definerer navn, beskrivelse og tilgjengelige verktøy. Innholdet er instruksjonene Claude følger.

Auto-trigger · Hvis description matcher konteksten, kan Claude bruke skillen uten at du skriver /<navn>.

---
name: pr-summary
description: Lag et lesbart sammendrag av en PR
allowed-tools: Bash(git *), Bash(gh *), Read
---

# PR-sammendrag

For PR-en denne sesjonen jobber med:

1. Hent diff og commit-historikk
2. Identifiser hva som endret seg
3. Pek på hvorfor — referer issue, kontekst
4. List risiko — migrasjoner, breaking changes
5. Foreslå test plan — hva må verifiseres

Format: markdown, klar for Slack-kanalen.

Hooks · konfigurasjon

Hooks i settings.json og shell-script.

.claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/auto-format.sh"
      }]
    }],
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/block-dangerous.sh"
      }]
    }]
  }
}
block-dangerous.sh
#!/bin/bash
CMD=$(jq -r '.tool_input.command')

if echo "$CMD" | grep -qE \
   'git push.*main|rm -rf|git reset --hard'; then
  echo '{"hookSpecificOutput":{
    "hookEventName":"PreToolUse",
    "permissionDecision":"deny",
    "permissionDecisionReason":
    "Farlig kommando blokkert"
  }}' >&2
  exit 2
fi
exit 0

Hierarki: ~/.claude/settings.json (du) → .claude/settings.json (team) → settings.local.json (gitignorert).

Moelven Industrier · AI-dag — Plugins
Bundling og distribusjon

Plugins — bundle og distribusjon.

Et plugin er en pakke som samler skills, hooks, slash-kommandoer og MCP-servere i én installerbar enhet. Plugin marketplace fra mars 2026 gir et offisielt distribusjonslag.

Hva et plugin inneholder
  • Skills · gjenbrukbare arbeidsflyter
  • Hooks · deterministiske scripts
  • Slash-kommandoer · faste funksjoner
  • MCP-server-konfigurasjoner
  • Agent-definisjoner
Praktisk bruk
  • /plugin for å bla i marketplace
  • Installer og oppdater med ett kall
  • Bygg eget plugin for teamets standarder
  • Versjonshåndtering og avhengigheter
  • Tillatelseskontroll på det dere installerer

Når dere har bygd en god kombinasjon av skills og hooks for prosjektene — pakk det som plugin og del.

Fra eksperiment til styrt forretningsprosess

Tre spørsmål ledelsen bør ha svar på.

Hvem bestemmer hva AI-en får gjøre?

Tre lag med policy: globalt → team → lokal. Hooks håndhever det som alltid skal gjelde — blokkering og logging skjer uavhengig av modellens vurdering.

Hvordan vet vi hva som ble gjort?

Audit-trail via PostToolUse-hooks. Alle fil-endringer, bash-kjøringer og MCP-kall kan logges sentralt. Modellen kan ikke slette historikken.

Hvem eier standardene på tvers?

CLAUDE.md og .claude/ er styringsartefakter — ikke bare teknisk config. Endringer via PR-prosess, som annen policy. Onboarding: én kommando.

KvalitetsportMekanismeAnsvar
Blokkere farlige handlingerHook PreToolUse · alltid aktivtPlattform-team / IT
Kode-reviewSkill /review · før PR åpnesUtvikler
SikkerhetsgjennomgangSkill /security-review · før produksjonLead / arkitekt
Audit-trailHook PostToolUse · logger til filPlattform-team

Trygghet handler ikke om å bremse. Det handler om å gjøre AI-bruk forutsigbar og sporbar.
